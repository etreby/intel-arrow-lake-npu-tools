# Changelog

## Unreleased

### Fixed

- Arabic text recognition would never have worked on openSUSE. The RPM recommended `tesseract-ocr-traineddata-arabic`, and openSUSE names its language data by the three-letter code, so the correct name is `tesseract-ocr-traineddata-ara`. A weak dependency that matches nothing is not an error: zypper drops it in silence and reports a successful install, so the package looked correct and the feature was simply absent.
- The RPM could not be installed on Enterprise Linux 9 at all. It required `python3 >= 3.10`, and EL 9 ships 3.9 as `python3` and will never ship anything newer under that name, so `dnf` refused the package outright. It now requires `python3.12`, which sits beside it in AppStream. `intel-npu-tools-setup` had the same assumption a layer down — it ran `python3 -m venv`, which even on a successful install would have built an environment too old to run any of this. It now takes the newest interpreter it can find that is both new enough and able to create an environment, and says which one it used. Requiring only a new enough version would have been its own bug: Debian ships the venv machinery separately, so `python3.13` without `python3.13-venv` must lose to a usable `python3.11`.
- The RPM suggested `grim` on Enterprise Linux, where no such package exists in either the distribution or EPEL. Same silent drop as the Arabic name, in a field that matters less.

### Changed

- The RPM and Arch packages are now built and installed on the distributions they are for, in containers, on every push. Until now neither had ever been installed anywhere — they were built, inspected and believed. The RPM is built twice, on Fedora and on openSUSE Tumbleweed, because the spec selects dependency names with an `%if` and a build on one distribution never evaluates the other's branch. The Arch package gets a real `makepkg -s` run and a `pacman -U` install, in place of calling its `package()` function directly.
- Dependency names are checked individually rather than being trusted to the install. Installing proves only that the required set resolves; a *weak* name that exists nowhere is skipped without comment by dnf, zypper and pacman alike, which is exactly how the Arabic package name survived. Names are read back out of the built package and matched against what the archive provides, so a virtual name like `ffmpeg` or `python3` — which openSUSE has no package called, and which is still the right thing to require there — passes, while a name nothing answers to fails.
- Every package is now installed on a distribution it targets, not only the RPM and Arch ones. The `.deb` was the last that nothing installed — it was built and unpacked — and Enterprise Linux was named in the spec's own comments as needing EPEL without anything ever having run there. Seven jobs now cover Debian, Enterprise Linux 9, Fedora, openSUSE Tumbleweed and Arch, each building the package on the distribution it is for, installing it, checking every dependency name, comparing the package's own manifest against the disk, and confirming that removing it takes back everything it owned and nothing shared.

### Added

- An AUR-acceptable `packaging/aur/PKGBUILD`, which the Arch package needed before it could be published anywhere: the AUR requires a versioned source fetched from a URL and checked against a `sha256sum`, and `packaging/PKGBUILD` deliberately builds from the working tree so unreleased work can be packaged and tested. Those rules cannot both live in one file, so there are two, and `scripts/update-aur-pkgbuild.sh` generates the second from the first — only the source line and its checksum are added, every dependency comes from the one file. CI regenerates and diffs, so the two cannot drift, and a container job builds it exactly as the AUR would, tarball fetch and checksum included. Publishing it to `aur.archlinux.org` still needs an account and an SSH key, and has not been done.

## 0.3.0 - 2026-08-09

### Added

- `intel-npu-panel`, a control panel with tabs for voice, screen reading, search, configuration and diagnostics. The two focused applications are unchanged: they exist to do one thing immediately from a keyboard shortcut, and a tabbed window behind those shortcuts would make dictation slower for no gain. Every NPU operation runs on a worker thread, because compiling a model takes seconds and doing that on the interface thread freezes the window.
- Settings persist in `settings.json` under the data directory, so the speech model, compiled-model caching and turbo can be changed from the panel rather than only by environment variable. Variables still win, so a one-off override on the command line keeps working; the panel names any variable currently masking a setting, because a control that silently does nothing is worse than one that explains.
- Screenshots and the clipboard work beyond KDE. Both were hard-coded to spectacle and wl-copy, so OCR failed outright on GNOME, COSMIC, sway and X11. Capture now picks from spectacle, cosmic-screenshot, gnome-screenshot, grim, maim, scrot and ImageMagick, and the clipboard from wl-copy, xclip and xsel, preferring whichever matches the running desktop and falling through when an installed tool fails.
- An application icon, drawn twice: the detailed version is correct from 48 pixels up, and a simplified one without package pins is used at 32 and below, where the pins dissolve into a fringe that eats the silhouette and the waveform bars merge into a block.
- Native packages for Debian, Arch and RPM distributions, all built from one staging script so they install the same tree. Only the .deb has been built and unpacked; the PKGBUILD and RPM spec are authored and linted but were written on a Debian derivative with neither makepkg nor rpmbuild, and the RPM's openSUSE dependency names in particular are unverified. They contain no models and no inference stack, and no maintainer script touches the network; `intel-npu-tools-setup` builds each user's environment instead.
- `context_filter` returns only the parts of a large local text file that answer a question, copied verbatim with the line numbers they came from. It exists to keep bulk text out of an AI agent's context window: on a 100 KB build log it returned four spans in place of 2,547 lines, an estimated 95 percent token reduction, and located a linker failure at line 1,400. Nothing is generated, so quoted lines can be cited; the reply also reports how many chunks were dropped and how close the best dropped chunk scored, because silent truncation otherwise reads as full coverage. Files under 4 KB are refused, since reading them outright costs fewer tokens than describing them, and files over 256 KB are refused because embedding them exceeds the tool timeout of several MCP clients. It reuses the embedding model already installed and needs no new download.
- Optional cross-encoder reranking for semantic search, behind `intel-npu-search search --rerank` and the `rerank` parameter of the `semantic_search` tool. Reranked hits gain a `rerank_score`, which is an unbounded logit and must not be compared against the cosine `score`. The model is a separate ~300 MB download via `scripts/download-models.py --with-reranker`; requesting reranking without it raises an error naming that flag rather than silently falling back.
- The Whisper model is selectable through `INTEL_NPU_TOOLS_WHISPER_MODEL`, naming a directory under the models directory. `scripts/download-models.py --with-whisper-small` fetches `whisper-small-int8-ov` (~250 MB), which compiles on the NPU and is more robust in noise: measured over eight recorded clips mixed with noise, it transcribed 8/8 correctly at 10 dB signal-to-noise where base managed 6/8, and 6/8 against 5/8 at 5 dB. The two are indistinguishable on clean audio and both fail equally at 0 dB. Base stays the default because small costs 2.6 times the latency, 237 ms per clip against 90 ms. English-only `medium` conversions were not adopted, since this project's speech support is multilingual.
- `screen_to_text` renders a screenshot as compact structured text rather than an image: reading order, a bounding box per line, and per-word boxes on request. A screenshot costs a vision model roughly 1,600 to 4,800 tokens; measured on a 1080p application window this returned the same screen at 33.7× less in `text` mode, 8.3× in the default `lines` mode, and 2.8× in `words` mode. `words` is not the default precisely because on a dense screen it can cost more than the screenshot did, and the reply says so when it has. Reading order comes from Tesseract's page segmentation rather than the `(y // 30, x)` row-banding heuristic used elsewhere in `ocr.py`, which stitches columns together — on a window with a sidebar, that heuristic returns a file name and an unrelated line of code as one line. Multi-page input is handled: `.tif` is an accepted type and Tesseract restarts its block, paragraph, and line numbering on each page, so lines carry a `page` number, bounding boxes are documented as page-local, and the reported image size is the first page's. **This tool leaves the NPU idle.** Its text comes from Tesseract, because the bundled NPU recognizer is a CTC model over a hardcoded 37-symbol lowercase alphabet and cannot emit capitals, punctuation, or non-Latin script. Replacing that model is the change that would make it an NPU feature; `docs/ROADMAP.md` records what is unknown about doing so.
- `scripts/benchmark.py` measures model load and inference times repeatably, so the figures in the documentation can be re-checked after a driver, firmware, or OpenVINO upgrade instead of being trusted indefinitely. Each measurement runs in a fresh subprocess, because every loader caches its compiled model per process; warm latency is a median so a single scheduler hiccup does not move it; and a provenance header records the driver, compiler, and OpenVINO versions it ran against. It deliberately does not clear the Level Zero driver's blob cache to obtain a cold-compile number, because doing so would slow the user's next session for every model they own.
- `docs/ROADMAP.md` records what is worth building on this hardware and what measurement ruled out.

### Fixed

- The project is named `intel-npu-tools` throughout, having previously carried both that name and `intel-arrow-lake-npu-tools` depending on where you looked. An installation predating the change keeps its models under the old directory name, so every component falls back to it when it is the one that exists; nothing is moved, because a directory rename is not something to do to a gigabyte of someone's files unasked. `scripts/download-models.py` was the one place this went wrong: run directly, as the documentation says to for the optional models, it built its own path and created the new directory, which would have made an existing installation's models, settings and semantic index appear to have vanished. It now asks the package where the data lives instead of recomputing it.
- `Meta+F9` and `Meta+Alt+O` now actually work. `install.sh` registers them in `kglobalshortcutsrc`, which is the only thing KDE reads. Speech moved off `Meta+Alt+S`: KDE's accessibility component binds that combination to "Toggle Screen Reader On and Off" on a stock install, so kglobalaccel discarded this project's binding at every login, leaving `_launch=,Meta+Alt+S,…` with an empty active field — registered in appearance, dead in practice. The installer now refuses to write an accelerator another component already holds and names the owner, rather than writing one that will be silently dropped. The `X-KDE-Shortcuts` line in each desktop file never did this: KDE honours that field for applications installed system-wide, but ignores it for a desktop file in `~/.local/share/applications`, so the documented shortcuts silently did not exist and the applications could only be started from the menu. Registration skips any application the user has already bound to a key of their own, and `uninstall.sh` releases both shortcuts so they do not stay bound to applications that are gone. The keys begin working at the next login, because KDE's shortcut daemon reads that file only at session start and restarting it mid-session would drop every other global shortcut.

### Changed

- OCR compiles its two models once per process instead of on every call, which made repeat calls 4.9 times faster (0.176 s to 0.036 s). A single screenshot previously paid full driver compilation twice before reading a pixel. Inference is now serialised behind the same lock, because a compiled model reuses one implicit infer request and concurrent MCP calls would otherwise race; this costs nothing, as the device already runs one inference at a time.
- Missing OCR models now raise a `FileNotFoundError` naming `scripts/download-models.py`, matching the speech and embedding paths, instead of surfacing a raw OpenVINO read error.
- Plugin properties for every NPU model now come from one place, `intel_npu_tools.runtime.npu_properties`.

### Not changed, and why

- **Reranking is off unless asked for.** Having the model installed does not enable it. Measured against this repository, the cross-encoder promoted the correct passage with a +4.95 score on a query it recognised, but on a query where every score fell near -6.5 it discarded the correct passage that plain cosine similarity had ranked first. It appears trustworthy only when confident, and presence of the model is not evidence the user wants that trade on every search.
- **Compiled-model caching is off by default**, available through `INTEL_NPU_TOOLS_MODEL_CACHE`. The Level Zero driver already caches compiled blobs, so an OpenVINO cache duplicates them, and while that driver cache is warm it saves almost nothing: embedding load went from 0.98 s to 0.89 s and Whisper from 0.50 s to 0.79 s. Its real benefit is avoiding the occasional cold recompile, which is expensive — one such run measured Whisper at 4.69 s — because the driver's cache is shared and evictable while a cache under the toolkit's data directory is not. The cost is roughly 340 MB for Whisper and 1.2 GB for the embedding model, plus a one-off 10.4 s first run, which is why it is a switch rather than a default. That first-run figure closely matches the "approximately 10.7 seconds" quoted in the semantic-search guide, which suggests that number described a cold compile rather than steady state.
- **`NPU_TURBO` is off by default** and is not expected to help. It measured 241.2 ms against 240.1 ms with it disabled; the compiled model was confirmed to report the property as enabled, so this is a real result rather than an ignored setting. The switch remains because the effect is workload-dependent.

## 0.2.1 - 2026-08-09

### Fixed

- Excluded directory names are matched only below the indexed root. Previously any ancestor named `build`, `dist`, `models`, or `venv` made a whole tree unindexable, and `index` reported zero files without explanation.
- `models` was removed from the exclusion list, which only hid legitimate source directories. Model directories are now recognised by the weights they contain (`.bin`, `.gguf`, `.onnx`, `.pt`, `.pth`, `.safetensors`) and pruned whole, so a source directory named `models/` is indexed while a Whisper or OpenVINO directory is not. Weights were always excluded by extension, but the text sidecars beside them were not: tokenizer vocabularies, merge tables, and OpenVINO IR graphs are `.json`, `.txt`, and `.xml`, and added megabytes of machine-generated data to every search.
- Cache directories are excluded: `.cache`, `.ipynb_checkpoints`, `.mypy_cache`, `.pytest_cache`, and `.ruff_cache`.
- `--root` and `semantic_search(root=...)` escape SQL `LIKE` wildcards. A path containing `_` or `%` previously matched sibling directories and returned passages from outside the requested scope.
- SQLite connections are closed instead of only committed, so the long-lived MCP server no longer accumulates handles and WAL files.
- Re-indexing a root now removes entries for files deleted from disk. Searches previously kept returning passages from paths that no longer existed. A row is dropped only when its file is genuinely gone, never because a traversal skipped it, so overlapping and nested roots can be indexed in any order without erasing each other. Indexing a path that has since been deleted now removes its entries instead of failing, which is the only way a user could drop one. "Gone" means `lstat` reports `ENOENT` or `ENOTDIR` *and* the recorded device still matches the nearest existing ancestor, so neither a permission error nor an unmounted disk can erase entries for files that are still there — an `os.path.exists` check would have erased both. Each file's device is recorded for this purpose; 0.2.0 databases gain the column automatically and fall back to the old check until their next index run.
- Chunks are capped so their tails are not silently dropped by the 512-token embedding limit, and an overlong single line is split rather than truncated. The chunker version is recorded per file, so indexing a root re-chunks that root's files while leaving every other indexed root intact.
- OCR no longer fails when Tesseract is missing or errors; it falls back to the NPU recognizer as documented.
- `__version__` is derived from package metadata instead of drifting from `pyproject.toml`.
- Closing the speech application mid-recording removes its temporary WAV file.

### Security

- The Level Zero loader `.deb`, which is unsigned on its PPA snapshot path, is pinned by SHA-256 and verified before installation.
- The driver installer verifies a detached signature for every package it installs, and installs exactly the packages it verified. It previously required only that some signature in the archive was valid, so a package shipped without its `.asc` would have been installed unchecked. A missing expected package now aborts the install.
- `uninstall.sh` canonicalizes `INTEL_NPU_TOOLS_HOME` before its `rm -rf` and refuses anything that does not resolve to a subdirectory of the user's home, so neither `..` nor a symlinked path component can direct the deletion outside it.

### Changed

- OpenVINO pins allow patch releases within the validated 2026.2 minor instead of one exact build.
- `index` reports `files_removed` and `files_rechunked`, and adds a `warning` field when no file was eligible.
- Databases written by 0.2.0 gain the per-file `chunker` column automatically on first open.
- CI installs the MCP SDK and import-checks every runtime module, so a broken import in the `intel-npu-mcp` entry point can no longer ship on a green build.
